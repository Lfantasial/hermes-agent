## 🔄 WAL(Write-Ahead Logging) 작동 원리

### **1. 기본 개념**

WAL은 **사전 로깅(Pre-logging)** 방식입니다.

```
┌─────────────────────┐
│   사용자 입력 수신   │
└────────┬────────┘
         │
         ▼
┌─────────────────────┐
│   에이전트 분석   │  ← WAL이 작업 수행
└─────────────────────┘
         │
         ▼
┌─────────────────────┐
│   WAL 로그 기록     │  ← WRITE-AHEAD 방식
└─────────────────────┘
         │
         ▼
┌─────────────────────┐
│   최종 응답 생성     │  ← WAL 로그 참조
└─────────────────────┘
```

---

### **2. WAL 로그의 구조

```json
{
  "type": "request",
  "timestamp": "2026-02-22T10:15:00Z",
  "user_query": "한국의 출산율 분석해줘"
}

{
  "type": "decision",
  "timestamp": "2026-02-22T10:15:01Z",
  "context": "한국 최저출산 원인 분석",
  "decision": "Codex에게 분석 작업 위임"
}

{
  "type": "response",
  "timestamp": "2026-02-22T10:15:05Z",
  "original_query": "한국의 출산율 분석해줘",
  "response": "🤖 [Codex] ...분석 결과..."
}
```

---

### **3. WAL 로그가 하는 역할

| 항목 | 역할 |
|------|----------|
| **1. 사전 기록** | 사용자의 모든 입력, 질문, 결정을 작업 전에 기록 |
| **2. 에러 수정** | 이전 응답의 오류를 즉시 수정하여 정확성 보장 |
| **3. 결정 추적** | 중요한 의사결정을 기록하여 다음 작업 참조 |
| **4. 응답 생성** | WAL 로그를 참조하여 정합성 있는 최종 응답 생성 |
| **5. 에러 기록** | 작업 실패 시 에러를 기록하여 추후 복구 가능성 확보 |

---

## 🎯 WAL이 작동하는 방식

### **1. 세션 시작 시 로드**

```
# 세션 시작 전 WAL 로드
load_latest_wal_entries()

# 사용자 질문 분석 및 작업 수행
```

### **2. 세션 진행 중 실시간 로드**

```
# 세션 진행 중 WAL 업데이트 (WRITE-AHEAD)
if is_complex_query(user_query):
    log_decision_to_wal("complex_analysis", user_query)
    spawn_codex(user_query)
else:
    tavily_search(user_query)  # 로컬 검색

# 작업 완료 후 WAL 업데이트
if task_complete:
    log_response_to_wal(original_query, codex_result)
    commit_wal_transaction()
```
