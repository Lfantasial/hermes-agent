# Daily Memory - 2026-04-26

## 03:00 - Daily Security Audit (Cron)

Executed `openclaw security audit --deep`

**Findings:**

1. **High - Trust Boundary Multi-User Exposure**
   - `channels.telegram.groupPolicy="open"` allows multiple users on same Gateway
   - Runtime/Process tools exposed without full sandboxing in some contexts
   - Risk: Potential privilege escalation in shared environment with untrusted users

2. **Medium - Phantom Plugin Allowlist Entries**
   - Unused entries in `plugins.allow` not matching installed plugins:
     - `telegram`, `memory-core`, `zai`, `openai`, `openrouter`, `ollama`
   - Risk: New plugins could spoof allowlisted IDs

3. **Medium - Extension Plugin Tools Reachable Under Permissive Policy**
   - `claude-mem` extension plugin enabled
   - Permissive tool policy in: `default`, `agents.list.main`
   - Risk: Plugin tools may be exposed when handling untrusted input

**Attack Surface Summary:**
- groups: open=1, allowlist=0
- tools.elevated: enabled
- hooks.webhooks: disabled
- hooks.internal: enabled
- browser control: enabled
- trust model: personal assistant (single trusted operator)

**False Positives Excluded:**
- tavily-search: `scripts/extract.mjs`, `scripts/search.mjs`
- claude-mem: `bun-runner.js`, `context-generator.cjs`, `mcp-server.cjs`, `smart-install.js`, `worker-cli.js`
- writing-skills: `render-graphs.js`

**Remediation Recommendations:**
1. Separate trust boundaries for multi-tenant scenarios
2. Clean up unused `plugins.allow` entries
3. Restrictive tool policies (`minimal`/`coding`) or explicit allowlists for untrusted input handlers

**Note:** Current config is optimized for personal assistant model (single trusted operator), not hostile multi-tenant isolation. No action required if operating within trusted environment.
